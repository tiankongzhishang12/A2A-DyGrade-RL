## 一、本轮六项硬性整改决定

### 决定一：统一论文题目

正式研究方向统一为：

> **面向模拟试卷级自动阅卷的质量约束多智能体动态路由方法研究**

英文暂定为：

> **Quality-Constrained Multi-Agent Dynamic Routing for Simulated Paper-Level Automated Scoring**

论文中的“模拟试卷”定义为：基于真实题目、真实学生作答、Rubric/参考答案和人工评分标签重组形成的多题评分 episode。它用于构造多题共享资源与序列调度环境，不声称对应现实中的某个 `student_id + exam_id` 原始试卷。

### 决定二：评分质量和严重错分风险绝对优先

论文不得采用“允许牺牲一定准确率换取成本下降”作为主叙事。统一原则为：

> **先通过相对于固定参考策略的零容忍质量准入门，再以准入候选中的 Quality Champion 作为质量保护基准；只有能够证明质量不劣于冠军的候选，才允许比较资源消耗。**

资源收益只有在固定参考准入门和 Quality Champion 保护门都通过后才允许报告为有效收益。如果某个策略成本更低，但最坏数据集严重错分、最坏数据集不安全停止、Macro-NMAE 或 Macro-QWK 任一项无法证明不劣于固定参考或质量冠军，则该策略判为不可行。

### 决定三：禁止人工为结果调阈值

本文不禁止预注册程序自动学习模型参数和校准操作边界，但禁止研究者根据结果主观修改：

- STOP 安全概率边界；
- baseline 的置信阈值；
- 能力画像支持度边界；
- 预算、质量门和选择顺序；
- checkpoint 候选范围。

主方法的升级、核验、二评、仲裁和下一 Item 选择由 Router 学习，不额外建立一组人工升级阈值。Severe/Extreme、QWK 分档和 Bootstrap 属于冻结评价协议，不是 calibration 的学习对象。

### 决定四：固定质量指标与统计检验协议

正式质量协议在 Pilot 和任何 Router 结果之前冻结：

```text
normalized gate error：合法最终分数使用归一化绝对误差；Deferral/未安全完成/无合法最终分数记为1
Severe Error：gate error > 0.25
Extreme Error：gate error >= 0.50，仅作补充敏感性指标
Unsafe Stop：STOP后发生Severe Error；主分母为全部STOP
Macro-NMAE：三个数据集NMAE的算术平均
Macro-QWK：分数归一化后固定映射到0..10共11档，分别计算dataset QWK再宏平均
统计单元：Paper级配对Cluster Bootstrap，5000次，单侧95%，零非劣效界
质量门：最坏数据集Severe/Unsafe的差值上界<=0，Macro-NMAE差值上界<=0，Macro-QWK差值下界>=0
```

### 决定五：最终职责严格分离

`train_fit`、`train_calibration`、Dev 和 Test 的职责冻结为：

| 阶段 | 唯一职责 | 明确禁止 |
|---|---|---|
| `train_fit` | 训练 Router、Stop-Risk Head、critics 和其他可学习参数；拟合能力画像 | 读取 calibration/dev/test，或在训练后根据其结果继续改参数 |
| `train_calibration` | 对每个固定 checkpoint 自动校准 STOP 安全概率边界；冻结质量参考、预算和支持度边界；组装完整 Policy Package | 在不同 Router/checkpoint 之间排名或选择最终冠军；进入梯度训练或 replay buffer |
| Dev | 对边界已经冻结的完整 Policy Package 执行各预算档位质量门，并跨预算资源排序选择唯一 Package/checkpoint | 重新拟合、移动或试探任何边界 |
| Test | 对唯一冻结方案进行一次性最终评价 | 任何学习、校准、筛选或返回调参 |

因此，`train_calibration` 只回答“每个 Router 应当怎样安全使用”，Dev 才回答“最终选择哪一个 Router”。

### 决定六：先拆题目组，再分别重建内部 Paper

不得把现有5,475份 train Paper 直接随机切成 `train_fit` 和 `train_calibration`。本地审计显示，这些 Paper 因共享 prompt group 已连接为一个整体，直接切 Paper 必然破坏 prompt 隔离或使拆分不可行。

正式顺序固定为：

```text
现有train主路由Item池（当前为27,375条paper_manifest引用Item）
→ 以dataset + prompt_group及exact-answer/leakage关系传递形成的connected component为不可拆分单元，确定性分配到train_fit/train_calibration
→ 目标比例约80%/20%，完整component与strict Paper可构造性优先
→ 在两个内部split中分别重新构造固定5题strict Paper
→ 生成独立internal item/paper manifests与audit
```

现有外部 `papers_train.jsonl/paper_manifest.csv` 保留为 prepared data 来源和审计证据，但其 `paper_id` 不直接继承为内部训练 episode。Dev/Test Paper 保持不变。

统一流程为：

```text
按题目组拆分train Item并分别重建内部Paper
→ train_fit：学习模型参数和策略
→ train_calibration：只校准STOP安全边界并冻结环境/参考配置，组装候选Policy Package
→ dev：只比较完整固定Package并选择唯一checkpoint
→ freeze：锁定模型、Prompt、指标协议、阈值、预算、质量门和checkpoint
→ test：一次性最终评价；不通过即如实失败
```

## 二、研究问题的最终定义

给定一份模拟试卷：

\[
P=\{x_1,x_2,\ldots,x_n\}
\]

每道作答为：

\[
x_i=(prompt_i,answer_i,rubric_i,reference_i,scale_i,type_i)
\]

系统拥有固定的多 Agent 池：

\[
\mathcal A=\{CheapAgent,MidAgent,StrongAgent,EvidenceAgent,ArbitratorAgent\}
\]

Router 在共享资源约束下进行序列决策：

\[
a_t=(i_t,o_t)
\]

其中：

- \(i_t\)：下一步处理哪道作答；
- \(o_t\)：执行基础评分、常规评分、深度评分、证据核验、独立二评、仲裁或停止。

Router 只能看到已经实际调用并付费获得的 Agent 输出，不能提前查看未调用 Agent 的 cache。每次新调用产生分数、置信度、证据或分歧后，状态更新，Router 再决定下一步。

本文研究的是：

> **在评分能力固定、信息逐步产生、多题共享资源的条件下，如何学习一个质量优先的动态 Agent 调度策略。**

本文不研究：

- 如何训练评分模型；
- 如何让 Agent 获得新的题型能力；
- 什么题目或什么考试可以被批改；
- 学生级能力、总分或身份建模；
- 任意考试的通用评分系统。

## 三、质量优先的优化原则

### 3.1 不使用质量—成本加权和作为主目标

不再以以下形式作为主目标：

\[
\max(QWK-\beta Cost)
\]

因为只要调整 \(\beta\)，就可以人为接受不同程度的质量损失，容易产生“为了节省资源而降低评分准确性”的结果导向。

### 3.2 使用约束优化

主目标改为：

\[
\min_\pi J_{resource}(\pi)
\]

满足：

\[
J_{error,g}(\pi)\le J_{error,g}(\pi_{ref})
\]

\[
J_{severe,g}(\pi)\le J_{severe,g}(\pi_{ref})
\]

\[
QWK_g(\pi)\ge QWK_g(\pi_{ref})
\]

其中：

- \(g\) 表示数据集或有足够样本支持的任务组；
- \(\pi_{ref}\) 是自动确定并冻结的质量参考策略；
- `error` 优先使用 normalized absolute error；
- `severe` 表示严重错分率；
- QWK 用于数据集级正式评价，不直接作为单条轨迹的即时 reward。

### 3.3 参考准入门、质量冠军保护门与资源词典序

正式模型选择分三层，并保持**同一个预算条件 Policy Package**适配 Tight/Medium/Loose，而不是为每个预算档位人工挑不同 checkpoint。

第一层是相对于冻结参考策略的零容忍质量准入门。候选 Policy Package 必须在每个预注册预算档位上分别通过 Paper 级配对 Bootstrap 非劣效检验；任一档位未通过、指标未定义或 readiness failure，Package 级 `Reference Admission Feasible = No`，不得进入后续选择。

第二层先在所有预算档位均通过参考准入门的**候选 Router Policy Package**中，完全不使用资源指标，按以下固定质量词典序自动确定唯一 `Quality Champion`；固定参考、Baseline 和消融结果只用于比较报告，不参与冠军或最终 checkpoint 选择：

```text
Worst-(Budget,Dataset) Severe Error（低）
→ Worst-(Budget,Dataset) Unsafe Stop（低）
→ Mean-Budget Macro-NMAE（低）
→ Mean-Budget Macro-QWK（高）
→ Policy Package ID（确定性并列规则）
```

随后，以该 `Quality Champion` 作为质量保护基准，对每个其他候选在 Tight/Medium/Loose 各预算档位重新执行同一 Paper 级配对 Bootstrap。差值改为“候选减 Quality Champion”，且仍使用零非劣效界：

```text
UCB95(max_dataset_delta_severe) <= 0
UCB95(max_dataset_delta_unsafe_stop) <= 0
UCB95(delta_macro_nmae) <= 0
LCB95(delta_macro_qwk) >= 0
```

四项必须在所有预算档位同时通过，候选才标记为 `Quality Protection Feasible = Yes`。`Quality Champion` 与自身比较时自动满足该门。若某候选严重错分率、不安全停止风险或总体评分质量不能证明不劣于 Quality Champion，即使资源更低也不得进入资源排序。

第三层才对 `Quality Protection Feasible = Yes` 的候选比较资源。Dev 对 Tight/Medium/Loose 等权聚合：

\[
\overline{C}=\frac{1}{|\mathcal B|}\sum_{b\in\mathcal B}CostPerPaper_b
\]

Elapsed Time、Agent Calls 和 A2A Exchanges 同理。固定词典序为：

```text
Reference Admission Feasible = Yes（所有预算档位通过）
→ Quality Protection Feasible = Yes（所有预算档位不劣于Quality Champion）
→ Mean-Budget Cost/Paper（低）
→ Mean-Budget Elapsed Time/Paper（低）
→ Mean-Budget Agent Calls/Paper（低）
→ Mean-Budget A2A Exchanges/Paper（低）
→ Worst-(Budget,Dataset) Severe Error（低，仅资源并列时）
→ Worst-(Budget,Dataset) Unsafe Stop（低）
→ Mean-Budget Macro-NMAE（低）
→ Mean-Budget Macro-QWK（高）
→ Policy Package ID（确定性最终并列规则）
```

因此，资源更少不再是通过参考准入门后的充分胜出条件。只有能够证明不劣于当前质量最优方案的候选，才允许依靠资源优势胜出。最终仍只冻结一个预算条件 Policy Package/checkpoint，不得手工改变 Quality Champion、质量保护门或排序顺序。

### 3.4 资源下降声明门禁

正式 Test 中只有候选通过以下 Paper 级配对 Bootstrap 零容忍非劣效条件，才允许声明“降低资源消耗”：

```text
UCB95(max_dataset_delta_severe) <= 0
UCB95(max_dataset_delta_unsafe_stop) <= 0
UCB95(delta_macro_nmae) <= 0
LCB95(delta_macro_qwk) >= 0
```

其中差值均为“候选减参考”。若任一指标未定义、任一置信区间跨0或未达到边界，候选均标记为 `Quality Feasible = No`。

如果没有任何 Router 策略通过质量门，则实验结论应为：

> 当前动态路由方法尚未在不损失评分质量的前提下获得资源收益。

不得降低质量门来制造正结果。

## 四、质量参考策略的自动确定

### 4.1 不手工指定对主方法最有利的参考

质量参考策略从预先固定且精确定义动作语义的候选集合中自动确定：

```text
Always-Cheap
Always-Mid
Always-Strong
Fixed Full Multi-Agent Workflow
```

### 4.2 按预算档位自动选择

参考策略候选集合在正式实验前冻结。在 `train_calibration` 上对每个预注册预算档位先执行 STOP/QWK readiness，再按固定质量优先顺序自动选择。这里选择的是质量门所使用的**参考策略**，不是在 Router checkpoint 之间选择最终模型：

```text
Quality Metrics Defined = Yes
→ Worst-Dataset Severe Error（低）
→ Worst-Dataset Unsafe Stop（低）
→ Macro-NMAE（低）
→ Macro-QWK（高）
→ Cost/Paper（低，仅质量并列时）
→ Elapsed Time/Paper（低）
→ Agent Calls/Paper（低）
→ A2A Exchanges/Paper（低）
→ Reference Policy ID（升序）
```

选定后生成 `quality_reference_manifest.json`，记录 `budget_id -> reference_policy_id`、所有候选、readiness、正式质量协议 hash、各数据集与 Macro 指标、完整排序键、数据/cache 指纹、随机种子和代码版本。若某预算档位没有任何候选满足 readiness，该档位直接标记 `quality_reference_readiness_failure`。

进入 Dev/Test 时不沿用 `train_calibration` 的指标数值，而是使用冻结的预算—参考映射，在同一 split、Paper、Agent cache 和预算档位上重新运行参考与候选并做配对比较。不得在看到 Dev/Test 后更换参考候选集合或映射。

## 五、禁止手工阈值后的自动学习机制

### 5.1 需要消除的手工阈值

不允许人工设置并反复调整：

```text
confidence < 0.6就升级
risk < 0.2就STOP
disagreement > 1就仲裁
coverage > 0.8就接受
为了结果把0.6改成0.55或0.7
```

上述固定数值如果来自研究者观察结果后的手工选择，将使实验缺少可信度。

### 5.2 “没有人工阈值”不等于“系统没有决策边界”

研究中需要区分两种边界：

1. **主 Router 的动作选择**：`ROUTE_MID/STRONG`、`VERIFY`、`A2A_ASK`、`ARBITRATE` 和下一 Item 由 Routing Q Head 直接学习，不再为这些动作逐项设置人工升级阈值；
2. **STOP 安全边界**：Stop-Risk Head 先预测当前停止导致 Severe Error 的概率，再由 `train_calibration` 使用冻结算法自动确定允许 STOP 的概率边界。

本研究消除的是：

> **研究者根据结果手工选择或移动边界。**

baseline 如果本身属于阈值路由，也必须在相同 `train_calibration` 上自动校准其阈值；Dev 不得继续调整。

### 5.3 学习“未解决评分风险”

用动态风险模型替代人工难度阈值：

\[
r_\theta(s_{i,t})=
P(\text{当前STOP将产生严重错分}\mid s_{i,t})
\]

风险模型输入只包含当前可观察信息：

```text
题目和Rubric特征
当前已获得分数
Agent置信度
Evidence覆盖
Agent分歧
调用历史
剩余预算
```

不输入：

```text
test gold
未调用Agent输出
人工标注的最优Agent
人工设置的Easy/Medium/Hard结论
```

### 5.4 自动校准 STOP 安全边界

`train_calibration` 不训练模型参数，也不在多个 Router/checkpoint 中选择最终方案。它只对每个已经固定的 checkpoint 执行同一套预注册校准程序：

1. 在 `train_fit` 上训练 Router 与 Stop-Risk Head；
2. 冻结该 checkpoint 的模型参数；
3. 在 `train_calibration` 上计算可停止状态的风险预测与真实 Severe 标签；
4. 自动确定该 checkpoint 的 STOP 安全概率边界；
5. 记录校准覆盖率、失败原因和 protocol hash；
6. 与冻结的质量参考、预算和其他配置组装为一个完整 Policy Package；
7. 不在 calibration 上比较不同 checkpoint 的资源排名或选择最终冠军；
8. Dev/Test 中保持该边界不变。

风险目标由已冻结质量参考和 V1.3 Severe 定义共同约束，而不是研究者随意指定。可以采用 conformal risk control、分位数校准或其他预注册等价方法，但算法一旦写入 plan，正式实验前不得根据 Dev/Test 结果更换。

若某个 checkpoint 找不到满足要求的 STOP 边界，该 checkpoint 的 Package 标记为 calibration failure，仍保留记录，但不进入 Dev 的可比较候选集合。

## 六、质量约束 CAG-CQL 的学习方式

### 6.1 不把所有目标压成一个手工权重 reward

不使用：

```text
reward = quality - 0.1*cost - 0.3*latency - 2*severe_error
```

作为唯一训练依据，因为其中的权重容易被人为调整。

### 6.2 分离质量与资源信号

建议分别学习：

- `quality critic`：预测最终 normalized error；
- `severe-risk critic`：预测严重错分和不安全停止风险；
- `resource critic`：预测未来 cost、elapsed time、calls、messages；
- `CAG encoder`：编码 Item、Agent、通信、评分结果和共享预算状态。

### 6.3 约束式动作选择

动作选择分两步：

第一步，过滤质量不可行或结构上非法的动作：

\[
\mathcal A_{safe}(s_t)
=
\{a: \widehat{Risk}(s_t,a)\le \alpha_{learned}\}
\]

第二步，只在质量可行动作中最小化长期资源：

\[
a_t^*=
\arg\min_{a\in\mathcal A_{safe}(s_t)}
Q_{resource}(s_t,a)
\]

也可以使用 primal-dual constrained CQL，由训练过程自动学习拉格朗日乘子，而不是研究者手工设置质量—成本权重。无论采用哪种实现，Dev 都必须先执行固定参考策略准入门，再自动确定 Quality Champion 并执行候选对冠军的质量保护门；只有质量保护可行 Package 才能按跨预算资源词典序选择唯一 checkpoint。

### 6.4 `STOP` 不是人工置信度规则

`STOP` 是 Router 学习的正式动作。安全层只保留与评分合法性有关的硬规则：

```text
至少已有一个合法分数
分数位于合法范围
不能存在尚未处理的确定性格式错误
预算状态合法
```

风险、证据和分歧是否足以停止，主要由训练得到的风险模型和策略决定，不由研究者人工编写大量阈值规则。

## 七、共享预算的自动确定与适应

### 7.1 四维预算继续保留

每份模拟试卷共享：

\[
B_P=[C_{max},T_{max},N_{max},M_{max}]
\]

对应：

```text
max_cost
max_elapsed_time
max_agent_calls
max_a2a_exchanges
```

第一版 `max_elapsed_time` 表示串行调用累计延迟，不声称建模真实并发 makespan。

### 7.2 当前预算只用于 fixture

当前配置：

```yaml
max_cost: 0.20
max_latency: 30.0
max_agent_calls: 12
max_a2a_messages: 6
```

仅保留为 fixture smoke 和工程验证默认值，不直接作为正式论文主实验预算。

### 7.3 正式预算不能人工挑选

真实 Agent Pilot 只用于验证质量、互补性、费用量级、延迟和 context catalog 可行性，Pilot 的资源分位数不得直接成为正式预算。

Formal Agent、Prompt、解析、成本定义与 context support catalog 冻结并生成 `train_fit/train_calibration` cache 后，按以下预注册程序自动产生正式预算：

1. 在完整5题训练 Paper 上运行固定 behavior/reference policies；
2. 统计每份 Paper 的 cost、elapsed time、calls 和 exchanges；
3. 使用实现前冻结的分位数规则生成 Tight/Medium/Loose 三档四维预算；
4. 保存 `budget_calibration_manifest.json`，记录输入 Paper、policy ID、分位数、结果、随机种子和数据/cache/config hash；
5. 正式 train/dev/test 不再人工移动预算档位。

预算档位是外部实验条件，不根据主方法是否取得优势进行调整。

### 7.4 单一预算条件策略

Router 将剩余四维预算作为状态输入：

```text
remaining_cost
remaining_elapsed_time
remaining_agent_calls
remaining_a2a_exchanges
```

训练时从预注册预算分布中自动采样，使同一个预算条件策略适应 Tight/Medium/Loose，而不是针对每个预算手工设计不同规则。

## 八、Agent 冻结与能力画像整改

### 8.1 冻结 Agent 的含义

冻结表示固定：

```text

max_tokens
输出结构
```

冻结不等于已经知道每道题哪个 Agent 最优，也不等于做完能力画像。

### 8.2 能力画像的含义

能力画像使用 train cache 自动估计：

```text

严重错分概率
置信校准情况
平均成本
平均延迟

不确定性
```

能力画像：

- 不改变 Agent；
- 不使用 test；
- 不直接输出最优 Agent 标签；
- 作为 Router 的可选历史先验；
- 必须设置无能力画像消融。

### 8.3 能力画像也不得手工修改

能力画像的：

- 分组字段；
- 最小支持样本数；
- 聚合公式；
- 校准方法；
- low-support 处理；

必须在正式 cache 前写入配置和代码，由程序自动生成。不得查看 test 结果后调整某个 Agent 的画像以改变路由。

### 9.4 Formal Cache 范围

Formal cache 以新的 internal manifests 为训练侧 split 来源：

Agent cache 只能作为隐藏环境查询表。Router 执行某动作后才能看到相应输出。Arbitrator 只能看到已经付费调用得到的意见，不能通过 context 间接获得未调用 Agent 的结果。

## 十、模型选择与实验结果报告规则

### 10.1 参考准入、质量保护与资源选择

所有完整 Policy Package 在 Dev 上由程序执行以下固定流程：

1. 对每个预注册预算档位，使用相同 Paper、Agent cache、预算和重采样索引，与该档位冻结参考策略做配对比较；
2. 按 Paper 为 cluster 进行5000次配对 Bootstrap，计算候选减参考的单侧95%置信边界；
3. 每个预算档位只有四项零非劣效条件全部通过，才标记 `Budget Reference Admission Feasible = Yes`；
4. 置信区间跨0、QWK无定义、STOP覆盖为0或正式指标输入不完整时，该预算档位准入失败；
5. 只有 Tight/Medium/Loose 全部通过参考准入门的 Package，才进入质量冠军确定阶段；
6. 完全不使用资源指标，按跨预算最坏 Severe、跨预算最坏 Unsafe Stop、跨预算平均 Macro-NMAE、跨预算平均 Macro-QWK 和 Policy Package ID 的固定质量词典序，自动确定唯一 `Quality Champion`；

8. 只有在所有预算档位均能证明 Severe、Unsafe Stop、Macro-NMAE 和 Macro-QWK 不劣于 Quality Champion 的候选，才标记 `Quality Protection Feasible = Yes`；
9. 只在质量保护可行候选中，按三个预算档位等权平均的 Cost/Paper、Elapsed Time/Paper、Calls/Paper、Exchanges/Paper 排序，资源并列后保留原质量指标与 Package ID 并列规则；
10. 自动冻结唯一预算条件 Policy Package/checkpoint，不按预算档位手工挑不同 checkpoint。

## 十三、V1.3 正式质量指标与统计检验协议

### 13.1 Gate Error 与未完成处理

对合法最终分数：

\[
E_i^{gate}=\frac{|\hat y_i-y_i|}{score_{max,i}-score_{min,i}}
\]

对 Deferral、预算耗尽后未安全完成、最终分数缺失/越界/不可解析或无合法 active cache 结果：

\[
E_i^{gate}=1
\]

这样不能通过放弃困难 Item 人为降低错误率。所有 NMAE 与 Severe Error 主指标均基于该 `Gate Error` 计算。

### 13.2 严重错分与不安全停止

\[
Severe_i=\mathbf{1}[E_i^{gate}>0.25]
\]

\[
Extreme_i=\mathbf{1}[E_i^{gate}\ge 0.50]
\]

`Extreme Error` 只作补充敏感性分析。`Unsafe Stop` 主指标为所有显式 `STOP` 中发生 Severe Error 的比例：

\[
UnsafeStopRisk=\frac{\#\{STOP\land Severe\}}{\#\{STOP\}}
\]

同时报告 `Unsafe Stop / All Items`、`Stop Coverage` 和 `Deferral Rate`。若 `STOP count = 0`，则 `UnsafeStopRisk = NA` 且 `Quality Feasible = No`，不能记为0。

### 13.3 Macro-NMAE

分别使用 `Gate Error` 计算 DREsS、ASAP-SAS、SAS-Bench 的 NMAE，再取不加权算术平均作为主指标 `Macro-NMAE`；全部 Item 直接平均的 `Micro-NMAE` 仅作补充。

### 13.4 固定11档 Macro-QWK

先将 gold 与合法预测分数按各自题目分值范围归一化到 \([0,1]\)，再按下式进行 half-up 映射：

\[
b_i=\min\left(10,\max\left(0,\left\lfloor 10z_i+0.5\right\rfloor\right)\right)
\]

QWK 必须使用完整固定标签集合 `0..10`，不得使用当前样本实际出现标签的 union 重新压缩距离。分别计算三个 dataset QWK 后做算术平均。每个 dataset 至少100条有效完成 Item、至少2个非空 gold bin，且 expected weighted disagreement 必须大于0；否则 QWK 未定义并触发 readiness failure。

### 13.5 配对 Paper Cluster Bootstrap

正式质量门固定使用：

```yaml
unit: paper
paired: true
replicates: 5000
confidence_level: 0.95
sidedness: one_sided
noninferiority_margin: 0
seed: 20260729
```

固定参考准入门中，候选与参考使用相同的重采样 Paper 索引；Quality Champion 保护门中，候选与冠军使用相同索引。两层都保留同一 Paper 内5道题的预算依赖，并对每次重采样计算“候选减当前比较基准”的指标差值，正式通过条件均为：

\[
UCB_{95}\left(\max_g\Delta Severe_g\right)\le 0
\]

\[
UCB_{95}\left(\max_g\Delta UnsafeStop_g\right)\le 0
\]

\[
UCB_{95}\left(\Delta MacroNMAE\right)\le 0
\]

\[
LCB_{95}\left(\Delta MacroQWK\right)\ge 0
\]

若任一指标未定义、置信区间未通过或跨0，状态为 `quality_noninferiority_inconclusive`，并令 `Quality Feasible = No`，不得视为近似相同。

### 13.6 冻结与敏感性分析

上述主协议在真实 Pilot 和任何 Router 结果之前冻结。补充报告可包含 Extreme Error、Micro-NMAE、全 Item Unsafe Stop Incidence 和其他预注册阈值曲线，但不得替代主质量门或据结果改变主阈值。

## 十四、整改后的研究创新点

### 创新点一：质量绝对优先的共享预算序列调度

将模拟试卷级多题阅卷建模为质量约束下的共享资源序列决策，而不是允许质量与成本随意加权交换。

### 创新点二：基于逐步证据的可变长度评分路径

Router 在看不到未调用 Agent 输出的条件下，根据逐步产生的分数、证据和分歧，自主学习评分、二评、核验、仲裁和停止路径。

### 创新点三：校准 STOP 安全边界与学习型升级行为

Stop-Risk Head 的概率边界在独立 calibration Paper 上自动校准；调用 Mid/Strong、核验、二评、仲裁和跨 Item 调度仍由 Router 学习，不退化为多条人工升级阈值。

### 创新点四：能力、通信和预算联合状态表示

使用 CAG 表示 Item、Agent、评分结果、通信历史、能力先验和剩余预算，并通过消融验证各状态信息的真实贡献。
